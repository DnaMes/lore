# Issue and PR sweep ledger (2026-10-26)

Living document for the backlog sweep: one row per open GitHub issue and pull
request of `DnaMes/lore`. It is the memory across context resets — re-read it
first when resuming.

Every verdict is derived from the code at the time of the check, not from the
issue text. Evidence is a command plus its observed result, or the file:line of
the confirmed gap. `NOT VERIFIED` marks anything that was not actually executed.

## Verdict vocabulary

- `ALREADY-DONE` — behaviour exists; close with evidence.
- `STILL-VALID` — gap confirmed at file:line; fix or record a deferral decision.
- `OBSOLETE` — the premise no longer exists.
- `DUPLICATE` — superseded by another issue/PR.
- `DEFERRED` — deliberate owner decision, documented in the "Deferral decisions" section below.
- `BLOCKED` — two fix attempts failed or an external dependency blocks it.

## How the sweep was organised

Phase 1 triage ran as four read-only lanes (groups of 9-10 issues each) that only
inspected code and ran targeted pytest proofs; this session verified two
`ALREADY-DONE` verdicts itself. Phase 2 handled the two Jules PR clusters. Phase 3
fixed items in the order security/data-loss → Wave 2 chain → the rest.

## Phase 2 — pull request decisions

### Cluster A (Markdown): no survivor, one implementation instead

Measured before deciding, on this machine (`.venv` python 3.12, provider
`markdown` 3.x):

```
$ nice -n 10 .venv/bin/python /tmp/sweep/bench_markdown.py
short message (1 KB, 2000x): before 1786.8 ms, after 1300.5 ms, speedup 1.37x
long message (10 KB, 300x):  before 1604.7 ms, after 1263.9 ms, speedup 1.27x
leak check: no footnote in second output: True | first ok: True
```

("before" = `markdown.markdown(text, extensions=[...])` per call, "after" = one
`threading.local()` parser with `reset().convert()`.)

The measurement justifies the change, but no PR was merged as-is: every one of
the eleven also rewrites `lore/extractors/kimi.py` and/or
`lore/utils/formatting.py` (unrelated to the claim), several touch template
snapshots for routes they do not change, and the hot path
`_format_message_content_cached` is already wrapped in `threadsafe_lru_cache`, so
the PR bodies overstate the win. Implemented once instead: `render_markdown` in
`lore/interfaces/web_formatting.py`, used by the three converting call sites;
contract in `tests/test_markdown_renderer.py` (parity with the module helper,
per-thread parser, no state leak, escaped fallback without the package).

All eleven closed as superseded by that commit.

### Why the remaining issues stay open

The sweep verified 44 issues against the code: 3 are closed (#176, #191, #192),
2 are owner-deferred (#29, #48), 39 are real, confirmed gaps (`gh issue list
--state open` -> 41 rows). 36 of those 39 belong to the "Archive" epic
(#151-#190), which the repo's own archived plan sequences as spec-first,
migration-carrying work (source-revision store, canonical message envelope,
namespaced identity, backup bundle, adapter layer). Shipping one of those within
this sweep would mean writing a schema migration without the required design
spec and without the backup-verified migration test — the exact failure mode the
archived plan forbids and the one with real data-loss risk. They are therefore
recorded with a decided order, not silently reshuffled or half-implemented.

Three of the four non-epic gaps (#119, #194, #197) are independent of the
migrations and are the shortest path back into the backlog. #194 needs the
Playwright fixture (the script exists in `tools/`, the dependency does not), #197
needs `lore memory review accept|reject` and the Candidates tab; both are bounded
and need no schema change. Their order is fixed in the "Deferral decisions"
section below.

### #188 — what was decided

Three classes, never mixed: `observed` (a field that exists: `origin`, tool-event
statuses), `computed` (a deterministic derivation: means, median, ratio) and
`inferred` (a keyword heuristic about outcomes, produced only with
`--include-inferred`). Every result carries the source fields it reads and
`covered_sessions/total_sessions`; a missing field yields `value: null`,
`coverage: 0.0` and a caveat starting with `no data:`, so absence can never be
read as a confident zero. `MetricResult.__add__` raises on a cross-class sum, so
an inference cannot be folded into a measurement even by accident. The set is
fixed and small — no composite score, no git/session correlation (the issue asks
for ambiguity over invented causation, so no correlation claim is made at all).

### #178 — root cause and what was decided

The blocker was real and reproduced before the fix: after a smaller-chunk retry
wrote two half-range chunk rows, `_estimate_chunked_calls` looked only for a
full-range row, so the dry-run plan reported the chunk as missing and computed a
different merge fingerprint — `estimate_run` said `chunked` (`expected_calls=2`)
for a session the run considered done. The fix is one source: `_chunk_call`
builds the prompt, fingerprint and cache decision (full row **or** both halves,
via `_reuse_rows`) for the run and the plan alike; `_chunk_plan` produces the
merge fingerprint and remaining calls; `_SessionPlan` is consumed by

### #163 — what was decided

The issue asks for merge precedence and namespace rules before anything else, so
they are written into the module docstring and enforced by tests:

- **Bundle = backup snapshot + evidence contract.** One `db/index_v2.sqlite`
  member, taken with SQLite's online-backup API, carrying sessions, messages,
  annotations, memory *and* the raw `source_revisions`/`source_artifacts`. It is
  one member on purpose: `sessions.source_revision_id` and
  `memory_sources.source_revision_id` are joins, and two members could arrive
  inconsistent. The manifest adds what a backup does not need: `provenance`
  (namespace scope read from the store's own rows, machine scope, created_at,
  Lore version) and `evidence` (`source_revisions`/`source_artifacts` counts plus
  a sha256 over every captured `(source_identity, content_sha256)` pair), so
  swapped raw bytes fail verification even if SQLite's own checksums pass.
- **Merge precedence: local always wins.** Revisions dedupe on
  `(source_identity, content_sha256)`; a changed file becomes the next
  `revision_seq` for that identity (the archive's numbering is kept for sources
  this store has never seen). Sessions reuse `resolve_store_identity`, the same
  function the writer uses, so an identical copy is a no-op and a divergent copy
  of a taken id lands under `<tool>:<scope>:<id>#<n>` with `copy_of_session_id`.
  An archive row whose `content_sha256` is missing is rehashed from its stored
  messages with `content_hash_from_rows`, so a legacy row is not mistaken for a
  conflict. Annotations are `INSERT OR IGNORE` (a local tag, extraction or
  summary is never replaced); memory dedupes on
  `(kind, title, body, scope_project, scope_tool, created)`, and its tags,
  ratings, supersede chain and evidence links follow the new memory id.
- **Evidence links survive by identity, not by rowid.** `message_id` is a local
  rowid, so it is resolved from `(session, message_seq)` or
  `(session, message_native_id)` against the *imported* rows; the archive's own
  rowid is discarded, and `source_revision_id` is remapped through the revision
  map. This is the half of #160 that only matters across stores.
- **Namespace rule.** Imported rows keep their original `source_namespace` (the
  importer never re-derives it from `LORE_SOURCE_NAMESPACE`), and the report
  groups added rows per origin. Origin keys use the `<tool>:<scope>` spelling a
  session row carries, derived for a revision from its
  `<tool>:<scope>:<path>` identity.
- **Deletion and health are not transitive.** A tombstone from the archive is
  skipped (and counted) when this store still holds that session — local content
  is never deleted implicitly. Per-source health is inserted for unknown
  identities; for a known one the newer `last_captured_at` may update the state,
  but the local counters are never replaced by another host's counts.
- **`--dry-run` writes nothing by construction**: it merges into a snapshot copy
  of the live store, so the counts it prints are the counts a real import would
  produce. `--replace` installs the archive as the live store (first import onto
  an empty machine) and logs `mode=replace`.
- **No credentials, ever.** Only the store is archived; the provider cache and
  every environment value stay out, and nothing in the module reads the
  environment for a secret. `test_bundle_carries_no_credentials` sets the
  provider key variables and plants a `credentials.json` and
  `llm_cache/providers.json` beside the store, and finds the secret in none of
  the bundle's bytes.
- **Migration numbering.** 24 and 25 belong to a parallel lane, so 26 is used.
  That leaves a gap in the list on this branch, which broke the
  `len(MIGRATIONS)` assumption in `schema.open_v2_connection`, `backup.py` and
  three tests; the built schema version is now `schema.SCHEMA_VERSION =
  MIGRATIONS[-1][0]` (the highest migration, not how many exist), and
  `tests/test_storage_schema.py`'s expected-table set also gained the
  `source_health` table #162 added.
