# Session view readability: what good AI-chat-history viewers do

Date: 2026-11-10. Scope: research only, no Lore code changed, nothing committed.
Question: how do the best tools render one coding-agent session so it reads well, and what is
worse in Lore's `/session/<id>` page (owner complaint: "really hard to read").

## Method and limits

- SpecStory: open-source CLI (`specstoryai/getspecstory`, `specstory-cli/pkg/session/markdown.go`,
  `pkg/providers/claudecode/markdown_tools.go`, `pkg/spi/fence.go`), a real exported session
  (`specstory-cli/.specstory/history/2026-07-09_22-30-57Z.md`), docs (`specstoryai/docs`).
  The VS Code/Cursor extension is closed: its VSIX was downloaded and inspected statically with
  REA (`rea inspect-artifact --json`, evidence in `~/.local/state/rea/specstory-vsix/inspect.json`).
  REA only gave an inventory (zip entries, a 1.4 MB `extension/dist/extension.js`); the markdown
  strings were read with `grep` on the bundle. REA does not claim format semantics.
- Comparable tools: READMEs and repo metadata from GitHub (`gh`). Source read only for SpecStory.
  Not run against real data, so no screenshots and no timing.
- Reddit: NOT VERIFIED. last30days returned `HTTP 403: Blocked` for Reddit, and WebSearch refuses
  reddit.com as a domain. Hacker News (12 items) and GitHub (5 items) were used instead, which is
  weak evidence on UX. Cursor and Codex viewers are thin: the GitHub search found only 0-3-star
  projects, and no mature Cursor chat exporter was found.
- Lore: read from `lore/interfaces/routes/sessions.py`, `lore/interfaces/web_services.py`,
  `lore/interfaces/web_formatting.py`, `lore/utils/text_processing.py`, and
  `lore/templates/session.html`, `session_pairs.html`, `base.html` (CSS). Visual rendering was not
  checked in a browser, so every width or line-length number below is an estimate from CSS.

## 1. SpecStory (CLI and VS Code/Cursor extension)

Links: https://github.com/specstoryai/getspecstory (CLI under `specstory-cli/`),
https://github.com/specstoryai/docs (`features.mdx`, `settings.mdx`, `integrations/vscode.mdx`).

**File naming.** `.specstory/history/<YYYY-MM-DD_HH-MM-SSZ>-<slug>.md`, for example
`2026-01-16_16-48-38Z-the-code-in-specstory.md`. The slug comes from the first user message
(`GenerateFilenameFromUserMessage`, lowercase, dashes, stopword-free words). When no words
survive, the name is only the timestamp (`2026-07-02_15-28-22Z.md`). `.specstory/.project.json`
holds project bookkeeping.

**Document structure (`GenerateMarkdownFromAgentSession`).**
- Line 1: `<!-- Generated by SpecStory, Markdown v2.1.0 -->`.
- `# <first exchange timestamp in UTC>`, then `<!-- Claude Code Session <id> (<ts>) -->`.
- Each record gets a role header: `_**User (2026-07-09 22:30:57Z)**_` or
  `_**Agent (<model> <ts>)**_`. Sidechain (subagent) messages are marked `- sidechain`.
- A `---` line separates exchanges and role changes. Within one agent turn, later records repeat
  the `_**Agent**_` header without a separator (code path in `renderMessage`).
- Optional `<!-- message-id: ... -->` comments.

**Thinking.** `<think><details><summary>Thought Process</summary> ... </details></think>`. Closed
by default, no word count, no preview.

**Tool calls.** `<tool-use data-tool-type="…" data-tool-name="…"><details><summary>Tool use:
**Bash**</summary> … </details></tool-use>`. Body per tool (`markdown_tools.go`):
- Bash: command in backticks, or a fenced block if multi-line; description line above.
- Read, Grep: path in backticks, pattern, include glob.
- Write: content in a fence with a language hint.
- MultiEdit: path only (the Claude formatter list has no Edit-specific diff renderer; the plain
  `Edit` tool was not checked in detail).
- Generic tools: `**Input:**` as a sorted `- key: \`value\`` list, then `**Result:**` or
  `**Error:**` and the full output in a fence. No truncation in the renderer I read.
- `<system-reminder>` blocks are stripped. Local-command caveat messages are kept, so the real
  sample shows raw `<local-command-caveat>` and `<command-name>` user turns. That is noise
  SpecStory does not filter.

**Code fences.** `spi.CodeFence` sizes the fence to one more than the longest backtick run in the
content, so tool output cannot break the document.

**Timestamps.** UTC, `YYYY-MM-DD HH:MM:SSZ`, in every header. Local-offset mode is optional.

**Diffs.** No line diff renderer in the Claude markdown path. Diffs appear only as whatever the
agent printed.

**Truncation and folding.** None in the markdown writer. The only folding is the `<details>`
elements.

**VS Code/Cursor extension (closed).** The VSIX bundle contains the same strings:
`Generated by SpecStory, Markdown v${…}`, `Thought Process`, `<tool-use data-tool-type=`,
`<details><summary>Tool use: **${…}**`. So the extension writes the same format as the CLI. The
reading UI is the editor's Markdown preview (or GitHub) with HTML `<details>`. Sharing goes to
share.specstory.com, which allows editing the page and adding GitHub links. (Lore's `/export/<id>`
route also exists; its output format was NOT checked.)

**What makes it readable.** One Markdown file per session, with a predictable header per
record, collapsed reasoning and tool output, and no custom UI. Its weak points are the
repeated headers and the untouched noise (caveat turns, unbounded output).

Searches for Cursor exporters found only 0-star projects. HN (12 items, 6.4k points) discussed
the Claude Code transcript and usage tools, not the reading UX. Reddit: NOT VERIFIED (blocked).

**Patterns that recur across the references.**
1. Tool activity is collapsed by default, and one control toggles it (claude-code-trace,
   tail-claude, claude-code-log minimal).
2. Long content is folded to a preview, not shown in full (claude-code-log minimal).
3. Turns are dense rows with a time rail, not large cards per record (claude-code-log minimal).
4. Sub-agents and forks are separate, foldable branches (claude-code-log, tail-claude).
5. The prompt TOC carries timestamps and summaries, and it stays in view (claude-code-log).
6. Live pages keep scroll position and folded state while they grow (claude-code-log `serve --watch`).
7. Diffs are word-level for edit calls (claude-code-trace).

## 3. Lore's current session view: what is worse

Structure as read (files under `lore/lore/`):
- Route `session_detail` in `interfaces/routes/sessions.py` (line 787). 40 **prompt pairs** per
  page (`MESSAGES_PER_PAGE = 40`, line 583), then a "Load more messages" button backed by
  `/session/<id>/messages`.
- Pairing in `interfaces/web_services.py` (about lines 430-493): each user message starts a pair.
  **Every** non-user message (assistant, tool, system, info) is appended as its own response.
- Rendering in `templates/session_pairs.html`: each response is its own `turn-row` with a
  `role-badge` (uppercase, letter-spaced label, AI/T/S/i icon), model chip, input and output token
  chips, and an `HH:MM` time, followed by a bordered, tinted card.
- Tool calls: `format_tool_calls` (`web_formatting.py` ~line 491) wraps consecutive calls in one
  `<details class="tool-group">`. Its summary is "N tool calls · Bash×3 · Read" and a status. Failed
  groups open by default. Identical consecutive calls fold into `×N` (`fold_tool_bursts`).
- Tool results: `format_tool_result` (`utils/text_processing.py` ~line 383) is a nested
  `<details class="action-block tool-result">`. The summary is the first output line cut to 90
  characters. The body is the full `<pre>` with no height cap (`.action-output` has `overflow: auto`
  only). Extractors cap at source (Codex 20k chars, Gemini 4000 chars with a `[truncated]` marker).
- Thinking: `<details class="think-fold">`, summary "Thinking · N words", closed by default
  (`data-thinking="fold"`).
- Find in session: server-side `api/session/<id>/find`, capped at 200 hits with 160-character
  snippets. Client marks, Prev/Next, and a status "N / M+". This is good.
- Prompt outline: desktop sticky sidebar (`toc-card`, width basis 550 px), mobile bottom sheet.
  Labels are cut to 88 characters and show only `HH:MM`. Clicking a prompt on an unloaded page
  loads pages until the anchor appears (`jumpTo` in `base.html`). This works, so it is not a bug.
- Typography and width: prose 14 px, line-height 1.75. The reading column is about 850 px (CSS
  basis), and user cards are capped at 920 px. At 14 px that is roughly 120-130 characters per
  line (estimate, not measured).
- Diffs: `format_diff` (`utils/text_processing.py` ~line 95) already renders unified diffs with
  +/- stats. It is used for some tool results (call site around line 512), so Lore is ahead of
  SpecStory here.

**What is worse than the references, concretely:**
1. **Chrome per record.** Each response gets a full badge row, chips and a bordered card, so an
   agent turn with several tool steps reads as many separate boxes. claude-code-log minimal uses
   dense rows on a time rail. Note: SpecStory also repeats headers per record, but in plain
   Markdown the cost is much lower.
2. **Tool group summary hides the target.** The collapsed bar shows names and counts only, not the
   file path or command. Scanning "what did it touch" means opening every group. claude-code-trace
   and tail-claude keep one row per call with its target.
3. **Tool results are not folded to a preview.** Full output is shown whenever the result is opened
   (no preview, no line cap). Long Bash or test output dominates the scroll. claude-code-log
   minimal folds these.
4. **Timestamps are `HH:MM` only** per record. Multi-day sessions lose the date (only the header
   has it). SpecStory writes full UTC timestamps per header.
5. **Reading column is too wide** (about 120-130 characters per line at 14 px, by CSS estimate),
   and the 550 px sidebar sits beside it. Long-form reading is harder than at about 70-90 characters.
6. **Prompt outline is prompts only.** There is no per-turn summary or timestamp range (claude-code-log
   has both) and no response-level navigation. Labels stop at 88 characters.
7. **Sub-agents and forks are not separate branches** in the session view (not verified for Claude
   sidechains in this code path; claude-code-log and tail-claude both do this).
8. **Thinking has only a word count** (no first-line preview), and is a separate full-width box.
9. **Caveat and command noise** reaches the view: `<local-command-caveat>` and `<command-name>`
   turns are shown as user prompts unless filtered by `noise_rules` (SpecStory shows the same
   noise, so this is a shared weakness; Lore already has noise rules, which is good).
10. **Pagination by prompt pairs** means a long assistant run can be a very tall first page, while
    the "Load more" button is at the bottom. claude-code-transcripts paginates by page file.

**Better than the references (keep):** `×N` burst folding, auto-open of failed groups, server-side
find with Prev/Next, word-level-capable diff with stats, token chips, lazy paging with TOC jump,
and the scroll-compact header.

## 4. Ranked design changes for Lore's session page

Effort: S = under half a day, M = 1-2 days, L = more. Reference: the source named in brackets.

1. **Merge one agent turn into one card** (one header per prompt-response turn; consecutive
   assistant and tool records share it, with a thin divider between steps). Why: removes the
   box-per-record fragmentation. Ref: claude-code-log minimal (time rail, dense rows), SpecStory
   (one exchange = one block). Effort: M (`web_services.py` pairing, `session_pairs.html`).
2. **One row per tool call in the collapsed group**, showing target and status
   (`Read  lore/…/web.py  ✓ 0.2s`, `Bash  pytest -q  ✗ exit 1`). Why: answers "what happened"
   without opening anything. Ref: claude-code-trace, tail-claude, SpecStory's `Tool use:` plus
   target line. Effort: S-M (`format_tool_calls`, `format_tool_display`).
3. **Fold long tool output to a preview** (first 8-12 lines plus "show N more lines") with a
   copy button. Why: long output is the biggest vertical cost. Ref: claude-code-log minimal
   (long content folded to short previews). Effort: S (`format_tool_result`, CSS `max-height`).
4. **Full timestamp in the turn header** (`2026-11-09 22:30`, date when the day changes, and a
   day separator). Why: multi-day sessions need dates at a glance. Ref: SpecStory headers, the
   claude-code-log time rail. Effort: S.
5. **Narrow the reading column** to about 72-80 ch for prose (cap `.prose` at roughly 720 px),
   keep code and tool output full width. Why: line length. Ref: general readability guidance,
   and claude-code-log's dense-but-bounded layout. Effort: S (CSS only, but check the TOC sidebar
   width too).
6. **Richer TOC**: label up to about 120 characters from the first line, plus turn duration or
   tool count, and a first-line preview of the answer. Why: the outline becomes a map. Ref:
   claude-code-log TOC (timestamp ranges and summaries). Effort: S-M.
7. **Sub-agent and sidechain branches**: render sidechain or sub-agent work as a foldable branch
   under its parent turn. Why: a long session can hide whole tasks inside one flat list. Ref:
   claude-code-log (branches, columns), tail-claude (drill-in). Effort: L (needs data check on
   Claude sidechain records first, NOT VERIFIED here).
8. **Thinking preview**: show the first line of the fold summary, not just "N words". Why: tells
   the reader what the reasoning was about. Ref: SpecStory (`Thought Process`) is weaker, so this is
   an improvement over both. Effort: S.
9. **Keyboard and collapse controls**: `e`/`c` expand or collapse all tool groups, `t` toggles one
   turn, `]`/`[` jumps between turns. Why: power reading without the mouse. Ref: tail-claude
   keys. Effort: S (JS in `session.html`).
10. **Hide caveat and command noise by default**, with a toggle. Why: stops `<local-command-caveat>`
    from reading as prompts. Ref: none of the references filter it well (SpecStory keeps it), so
    this is a Lore advantage to lock in. Effort: S (`noise_rules`).
11. **Live follow that keeps scroll and fold state** when the session grows. Why: the owner reads
    sessions while they run. Ref: claude-code-log `serve --watch`. Effort: M (uses the existing
    live endpoint).
12. **Word-level diffs for Edit results** in the same card as the call. Why: change review.
    Ref: claude-code-trace. Effort: M (diff code exists, wiring is needed).

## 5. Phase 1: smallest change with the biggest readability win

Ship these together, all in templates and the two formatters (no data model change):

- **#2 one row per tool call** with target and status in the collapsed group.
- **#3 fold long tool output** to a preview with show-more.
- **#5 narrower prose column** (CSS).
- **#1 merge a turn into one card** (pairing in `web_services.py` plus `session_pairs.html`).
- **#4 full timestamps and day separators.**

Expected effect: fewer boxes, far less vertical space per tool step, and the target visible without
opening anything. Verify with a screenshot pass of 3 real sessions (long Bash, multi-day, subagent)
on headless Chromium, before and after. Visual claims are NOT VERIFIED until that run.

Phase 2: #6 TOC, #8 thinking preview, #9 keys, #10 noise. Phase 3: #7 sub-agent branches, #11 live
follow, #12 word diffs.
