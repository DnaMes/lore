How Lore works, what each term means, and how to find things fast.

What Lore does

Lore is a local-first library of your AI coding sessions from many tools. Nothing leaves this machine unless you opt in.

See docs/WEB-UI.md for web interface details.

Glossary

Session
One conversation with one tool.
Prompt
A message you sent.
Project
The working folder a session ran in. Sessions of different tools in the same folder share a project.
Thread / Timeline
All sessions of one project folder across tools in time order. The Threads page is reachable from a project and from Settings.
Memory
Facts, decisions and lessons any tool can write via lore memory add or MCP, and recall later. See docs/MEMORY.md.
Candidate
A memory proposed by a tool and waiting for your accept or reject on the Memory page.
Automated session
Runs started by scripts, cron or sub-agents. Hidden by default and shown with the show link.
Rules
The AGENTS.md and CLAUDE.md files collected from your projects.
Noise rules
Switches that hide boilerplate such as injected system tags when reading a transcript.
Library
The Markdown vault lore library writes under ~/.lore/library.

Finding things

Press Ctrl/Cmd+K anywhere to open search.

Put words in quotes for an exact phrase. Unquoted words are prefix-matched and all must match.

Title matches appear first. Use the filters on the Sessions page to narrow by tool, project, tag, or date.

When hybrid search is active, match: semantic hits appear only after keyword hits.

Sync

The Sync menu in the top bar reloads sessions from all tools or a single provider, runs a full rebuild when incremental sync misses changes, or audits the index against live files. A host timer also syncs in the background.

Privacy

Lore is local-first with no telemetry. The web server binds to loopback only by default.
